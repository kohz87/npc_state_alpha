Such failed transport remains intact in raw host message bytes for diagnosis/recovery but is excluded non-destructively from future prompt/history projection. Missing, malformed, truncated, duplicate, or non-terminal transport never triggers regeneration, a fallback scanner, or another provider call.
  * **Strict immediate authority:** One-pass proposals are parsed and validated by the S1 C04 schema and committed through `CommitCoordinator` as `WRITERS.ONE_PASS`. S3 may update only C02 immediate-owned identity/admission, presence/activity, live state (`status` is the canonical current activity/physical-condition field), `offscreenActivity`, presentation, established `currentForm`, numeric player relationship evaluation, and lifecycle/death. Development-owned durable fields remain rejected. New/unknown form definitions are not created by S3.

It exposes current immediate continuity, relationship axes, read-only established appearance-form IDs/names for `currentForm` selection, and read-only durable context where needed without advertising Development fields as one-pass write channels. The immediate output contract requires one terminal trailer and relationship evaluation for exchange-active NPCs.
  * **Replay and branch safety:** Finalized candidate processing is serialized to prevent concurrent duplicate commits. Memory and durable dedup keys suppress replay across adapter reloads. Committed source fingerprints, swipe IDs, and exact preceding lineage are revalidated against current host history. Replacement/regeneration on an already committed position and prior-branch divergence fail closed rather than layering state; S6 owns history reconstruction/rollback.
  * **Continuation:** SillyTavern continuation appends to the same assistant message position. S3 may remove a prior valid Alpha trailer from the continuation base only when that exact prior dedup key is already durable. Malformed/uncommitted prior transport is preserved and blocks fast mutation. Continuation pending-review identity includes the new assistant fingerprint so the later Development handoff does not collide with the earlier source revision. Foreign `extra.display_text` ownership is preserved.
  * **Transport-only rendering:** After a checked durable commit succeeds, Alpha temporarily stages only `message.extra.display_text` so SillyTavern's first `addOneMessage()` render does not flash the machine trailer. Raw `message.mes` and swipes remain untouched. On `CHARACTER_MESSAGE_RENDERED`, Alpha performs durable-key reconciliation and restores only its temporary display metadata. Existing foreign display overrides are not overwritten. Reload/chat-change reconciliation hides only transport proven by durable dedup state; uncommitted transport is never presented as synchronized success.

Because SillyTavern's public save wrapper can swallow errors, S3 uses the official same-origin `/api/chats/save` or `/api/chats/group/save` endpoint directly with host request headers and requires both HTTP success and `{ok:true}` before reporting commit success. Character saves retain the normal host chat header and target identity; group saves use the actual group chat file ID (`group.chat_id`), not the selected group entity ID. Server integrity checks and Alpha revision CAS both remain active. Client metadata/cache advance only after acknowledgement and only if the active chat still matches the captured target after the awaited save.

  * **Atomic pending bookkeeping:** Pending resolution occurs in the same CAS transaction as Development proposals, observations, accepted support, and review receipts. Deferred/failed/unavailable status is persisted as runtime-owned pending metadata; successful reviewed scope is removed only with a matching non-deferred receipt.
  * **Reload/recovery:** Pending work is durable in `npc_state_alpha.v1`; scheduler/provider instances are ephemeral. Re-instantiating storage/coordinator/queue resumes the durable pending ledger. Provider failures do not tight-loop automatically; manual retry or fresh evidence can make work eligible again.
